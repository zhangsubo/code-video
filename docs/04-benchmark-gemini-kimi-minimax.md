# 04 · Gemini vs. Kimi vs. MiniMax 三方实测耗时与 Token 账单深度评测

本报告对同一真实开源产品（macOS 原生 AI 配额管理应用 `TokenUse`）在三套主流大模型与智能体方案下从零独立制作商业级 `1920×1080 @ 60fps` 产品介绍视频的全过程进行了**毫秒级耗时拆解与精确到个位数的 Token 审计**。

---

## 一、数据采集口径（零估算）

所有统计均直接解析自本机三套客户端的原始遥测数据库与会话日志，口径与 `TokenUse` 自身 `NativeUsageService.swift` 完全一致，且**严格剔除了外层做方案调研、撰写规范文档与跨终端调度的非视频制作消耗**：

1. **Gemini（Antigravity）**：解析会话 SQLite 库（`step_type = 15` Protobuf 逐轮精确记录）与 `transcript.jsonl`，剔除前期阅读 `opus-video-prompts`、撰写方案文档及后续调度 Orca / MiniMax 的全部轮次，仅保留纯视频制作的 36 轮。
2. **Kimi Code（`kimi-code/k3.1-pro` via Orca）**：解析独立视频会话 `wire.jsonl` 全部 85 条 `usageScope = "turn"` 记录，并单独剥离 2 次 Orca 终端清理确认菜单的人工等待时间（共 `70.0s`）。
3. **MiniMax 三模态（`minimax/MiniMax-M3` + `speech-2.8-hd` + `image-01` via `mcode`）**：解析 `~/.minimax/v2/sqlite/runtime-state.sqlite` 独立视频会话 `mvs_1b64d7a5d5f74aa29bbdc203b069ea66`（共 119 轮），结合 `messages.jsonl` 中每步 `commandTimerStartedAt` 与 `effective_wait_ms` 做无重叠毫秒级推理/工具拆分，并汇总 [voiceover-stats.json](../cases/tokenuse-minimax/voiceover-stats.json) 与 [image-stats.json](../cases/tokenuse-minimax/image-stats.json) 的真实多模态调用量。

## 三、关键规律与实战结论（适合写作引用的核心洞察）

### 1. 大模型做一支商业级代码视频的「有效产出常数」在 `70K ~ 105K` Output Tokens
- 无旁白纯代码视频：Gemini 输出 `82.6K`、Kimi 输出 `70.7K`；
- 加上语音主时钟合成、AI 光学底板脚本与两轮自愈调优后：MiniMax 输出 `105.0K`。
- 真正拉开账面总 Token 差距的并非模型写代码的废话量，而是 **Agent 循环轮数 × 当前上下文长度** 带来的 `Cache Read` 累加（占 Kimi 与 MiniMax 总 Token 的 **95%~97%**，但按各家缓存计费规则，单价通常仅为普通输入的 10%~25%）。

### 2. 决定渲染挂钟时间的是「管道编码格式」与「Chrome 进程隔离」
- **JPEG `q=95` vs. 无损 PNG 管道**：`180fps` 超采样下，PNG 单次 24 秒全量渲染需 `~270s`，而 `JPEG (quality: 95)` 仅需 `~90s`（提速 `3×`），经 `tmix` 融合后肉眼无损。
- **4 独立 Chrome 实例 vs. 单实例 4 后台标签页**：MiniMax 实跑中发现单浏览器多后台 Tab 会触发 Chromium 合成器后台节流，改用 **4 个独立无头 Chrome 进程分片并行** 才能稳定吃满多核吞吐。

### 3. 多模态「真看真听」门禁不可被纯数值脚本替代
- Kimi 通过 `ebur128` 数值门禁成功抓到了 `loudnorm` `96kHz` 升采样与 AAC 真峰值微超标；
- 但 MiniMax 首轮混音虽然**数值上通过了 `-14 LUFS`**，却存在立体声平面序 `(2, N)` 与 `+32768` 直流偏置叠加导致的撕裂杂音——正是靠 `mcode-tools` 的 `videos_understand` **真实听觉审片**才当场拦截并修复至相关性 `0.99`。

## 四、选型决策建议

| 你的目标场景 | 首选方案 | 理由 |
|---|---|---|
| **最快速度出片（20 分钟级）、连续丝滑实机演示** | **Gemini 方案** | 单轮大块吞吐轮数最少（36 轮），原生直接读取本地 `.mp4` 视听双审，无需上传临时 URL |
| **高密度中文观点卡点、杂志感硬切动态海报** | **Kimi 方案（Orca）** | `k3.1-pro` 中文短句凝练度与瑞士网格秩序感极佳，切点边界校验极其严谨 |
| **正式对外发布片、需要真人级配音解说与摄影级质感** | **MiniMax 三模态方案** | 唯一打通「高清人声旁白 + 毫秒字幕主时钟 + AI 摄影底板 + 代码级锐利 UI」完整闭环，折算每秒成片耗时反而最快（`54.6s/s`） |
